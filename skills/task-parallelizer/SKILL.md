# 任务并行拆分执行

## 触发条件

用户任务涉及多个独立子任务、明确要求并行执行、或涉及多个 agent 协作时激活。

## 核心原则

1. **异步优先**：默认异步，不阻塞主 agent
2. **单写者**：同一工作区同一时刻只有一个 writer；只读 agent 可与 writer 并行
3. **父 agent 主导**：父 agent 编排决策，子 agent 不自行启动孙子 agent
4. **升级决策**：子 agent 遇未批准的产品/架构决策时，请求父 agent 决定

## 执行流程

### 1. 任务分解

| 判断标准 | 说明 |
|----------|------|
| 可并行 | 无数据/接口依赖，操作不同文件 |
| 需串行 | 子任务 B 依赖子任务 A 的输出 |
| 只读不冲突 | 审查、安全审计等，可与任何实现并行 |

分解后输出任务分解表，标注每个子任务的类型、依赖、可并行性。

### 2. Agent 分配

按角色匹配，不硬编码名称：

| 子任务类型 | Agent 角色 | 模式 |
|-----------|-----------|------|
| 架构设计/技术方案 | 设计类 | 先串行 |
| UI/UX 设计 | UI 类 | 可并行 |
| 后端/前端实现 | 实现类 | 可并行（单写者） |
| 安全审计/代码审查 | 审查类 | 可并行（只读） |

### 3. 调度模式

| 场景 | 模式 |
|------|------|
| 独立子任务 | 全部并行 |
| 有依赖的流水线 | 先串行后并行 |
| 多 writer 同目录 | 工作区隔离 |
| 实现 + 审查 | 混合并行 |

### 4. 结果汇总

收集输出 → 冲突检查 → 生成报告 → 处理待办

## 五种并行模式

### 模式 A：前后端并行

```
设计 → 后端实现 ∥ 前端实现 → 汇总
```

### 模式 B：多页面并行

```
设计 → 前端实现 × N → 汇总
```

### 模式 C：实现 + 审查并行

```
设计 → 实现 ∥ 审查（只读） → 汇总 + 修复
```

### 模式 D：设计 + 实现流水线

```
设计 → UI 设计 ∥ 后端实现 → 前端实现 → 汇总
```

### 模式 E：分阶段修复（Staged Fix）

```
阶段1：并行只读规划 → 阶段2：单一 writer 修复 → 阶段3：并行只读验证
```

审查发现多个独立问题时使用，阶段1/3 可并行，阶段2 必须单 writer。

## 验证合约

启动实现类子任务前，定义验收标准：期望行为、验证命令、证据要求、边界条件。

## 提示词规范

给子 agent 的任务描述应包含：目标、范围边界、上下文、成功标准、硬约束、验证方式、输出格式、停止规则。

## 关键约束

- 同一文件只允许一个 writer；同目录多 writer 需工作区隔离
- 审查类 agent 为只读，不占用写锁
- 设计必须先于实现
- 不给可写子 agent 硬性步数/工具数限制
- 审查后父 agent 合成再修复，不让多个 reviewer 各自改文件
